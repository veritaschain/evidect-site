# 公開された再現案内のブラウザ確認

状態: first-party UI test。セキュリティ認証、独立再現、アクセシビリティ適合認証ではありません。

`browser_check.py` は実際の公開HTTPSページをChromiumで開きます。ローカルのHTMLや保存済みの成功レポートへ切り替える機能はありません。期待するHTML/CSS/JavaScriptは指定したGitコミットから読み、ブラウザが受信した本文と比較します。公開版と指定版が違えば失敗として残します。

## 実行

Git履歴を取得した作業コピー、Python 3.10以上、Playwright 1.57.0と対応するChromiumが必要です。CIではブラウザ用依存を一時的なvenvへインストールします。観測・署名・オフライン再現ツールの依存関係には追加しません。

```sh
python3 -I -B tools/site-verification/browser_check.py \
  --expected-commit <配信済みの40桁コミット> \
  --output ./new-browser-results
```

新規の出力ディレクトリを指定してください。既存ファイルを再利用・上書きしません。セットアップ失敗や途中終了では成果物がない場合があります。古いHTMLやsummaryを今回の成功として扱わないでください。

## 確認範囲

320・390・768・1280pxの4幅、JavaScript有効・無効の計8条件を、毎回新しいブラウザコンテキストで確認します。

- 公開HTML、3つのCSS、JavaScript有効時の共通スクリプトが指定コミットと一致すること。要求されたアイコン等も指定版と照合します。
- 日本語の見出し、版を固定した実行コマンド、未評価・プライバシーの注意書きが存在すること。
- 横はみ出しがなく、本文スキップリンク、Enter/Escapeでのメニュー操作、再現案内へのページ内移動が機能すること。
- 移動先の見出しや案内リンクが他の要素に覆われないこと。
- 詳細手順と報告先リンクの宛先が指定どおりであること。

**外部リンク先へ移動せず、GitHubのIssueを投稿しません。** リンク先のログイン・投稿画面の動作確認は含みません。キーボードの基本操作テストをもってWCAG等への適合とは扱いません。Safari/Firefox、実機iOS、すべての利用者設定は対象外です。動きの低減を設定したChromiumでの確認です。

## 読み取り専用の境界

宛先は固定の公開サイトと、指定ソースのHTMLが参照する既知のローカルアセットだけです。GET以外、リダイレクト、予期しない宛先・クエリ、WebSocketを拒否します。Service Worker・ダウンロードを無効化し、ログイン状態や保存済みプロファイルを読みません。フォーム送信や顧客データの入力は行いません。

応答の検査はPlaywrightが取得した復号済み本文に対するもので、HTTP転送符号化そのものの一致ではありません。1 MiBのサイズ検査は本文取得後であり、ハードなネットワークメモリ上限ではありません。ページ読み込み・操作のタイムアウトとCIジョブの10分上限を別途適用します。

通信エラーやブラウザ起動不能は未確認、観測できた表示・本文の不一致は失敗です。別の条件が成功しても失敗は隠しません。`PASS`は8条件が満たされたという意味だけで、安全性・法令適合・証拠の真正性を示しません。

## 出力とCI

成功した各条件の公開ページの画面キャプチャと、そのハッシュ、ブラウザ版、指定コミット、結果を`summary.json`へ保存します。未署名・編集可能な、実行時点の記録です。全条件成功で終了0、不一致で1、未確認で2となります。プロセス終了コードと今回新規に生成されたsummaryの両方を確認します。

既存の`Deployed reproduction entrypoint`ワークフローに、公開HTTP照合成功後のブラウザジョブを追加します。同一リポジトリPRは配信済みbase、Pagesイベントはbuild.commit、手動実行は指定コミットを確認します。定期実行や外部通知は追加しません。権限はcontents:read、checkout資格情報は保存せず、秘密・実運用証拠は使いません。公開画面と要約の成果物を30日保存します。

16件のオフラインテストは宛先制限、不正応答、本文不一致、アセット不足、出力上書き拒否などを検査します。模擬応答による単体テストの成功と、公開ブラウザの実行成功は別の記録として扱います。
